# 邮件中心 1.0.0

Halo 自带的通知邮件只能改内容，不能主动拿去发给谁。这个插件补上的是「拿模板发信」这一整段。

## 这个版本能做什么

**站内模板一次看全。** 扫描站点上全部通知邮件模板，按通知类型分组列出，每条都能直接预览渲染结果。哪一类通知有模板、邮件通知器是否开着，页面上直接标出来，不用再去别处翻。

**自定义模板。** 新建模板时写标题、HTML 正文和纯文本正文，声明模板变量并给一个示例值；站内模板可以一键复制成自定义模板再改，不用从空白开始。保存前有语法检查，出错会指到具体的部分和行列。

**手动发信。** 收件人支持三种来源：站内用户（读账号邮箱）、访客（从历史评论里提取邮箱地址）、手动输入任意地址（一行一个，逗号分号都认）。发送前可以预览，发送后逐条显示成功或失败和具体原因。

**触发规则。** 评论、注册、发布三类事件可选；收件人可以是事件当事人、被评论文章的作者，或者额外追加的固定邮箱；规则还可以再挂一个 SpEL 条件，例如只在评论内容命中某个词时才发。规则只处理启用之后产生的内容，历史数据不会被补发一遍。

**给代码留的接口。** 一串触发密钥加一个 POST 接口，外部脚本带上 `X-Mail-Key` 请求头就能触发发信；模板名写 `builtin:` 前缀时走 Halo 自带的通知模板。接口按来源 IP 限流，密钥可以随时重新生成，重新生成后旧密钥立即失效。

**发送记录与自动清理。** 收件人、模板、标题、状态、耗时和失败原因全部留档，按设置的保留天数和条数上限清理。

## 发信账号

默认直接复用「设置 → 通知 → 邮件通知」里已经填好的 SMTP，站点原来能收到通知邮件，插件装上就能用；想把插件发信和 Halo 通知分开的，可以在插件里填自定义 SMTP，密码存放在 Secret 而不是 ConfigMap。两种方式都有发送测试，失败时给出可处理的原因。

## 环境要求

- Halo 2.26.0 及以上
- 站点已在「设置 → 通知 → 邮件通知」中启用邮件通知，或在插件里配置自定义 SMTP

## 安装

下载下面的 `plugin-mail-center-1.0.0.jar`，在后台「插件 → 安装」里上传并启用，左侧「工具」分组下会出现邮件中心的入口。

## 两点说明

- 自动触发的去重做在发送记录层：记录名由规则名、事件类型、事件对象和收件人哈希得出，重启、重新部署或扫描变慢都不会重复发送。
- 清空发送记录会影响这层去重，回看窗口内的事件有可能被重新发送一次。
