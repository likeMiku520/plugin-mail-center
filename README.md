# 邮件中心

把博客里所有能发出去的邮件模板集中到一处，手动挑一个发给某个人，或者写一条规则让博客自己在合适的时候发出去。

Halo 自带的通知邮件模板散在「通知」里，只能改内容，不能主动拿去发给谁；这个插件补上的是「用模板发信」这一段：模板看得见、收件人挑得到、发出去有记录、代码也接得上。

## 功能

**站内模板一览。** 扫描站点上全部 `NotificationTemplate`，按触发它们的通知类型分组展示，每条模板都能直接预览效果。邮件通知器是否开启、某一类通知有没有模板，页面上都有明确标注，不用再去别处翻。

**站内模板可以直接改。** 标题、HTML 正文、纯文本正文都能编辑，保存前有语法检查。编辑面板会把这个通知类型能用的变量全部列出来，点「插入」就写进光标位置。第一次保存会给模板打上 `halo.run/do-not-overwrite` 标记，Halo 升级时不再用自带的那份覆盖；点「重置」会还原成 Halo 出厂内容并把这个标记摘掉，之后重新交回 Halo 管理。

**测试邮件也能改。** 「发信设置」里那个发送测试按钮用的就是一封模板，它排在站内模板最上面，可以编辑、预览和重置，改完下一次测试就按新的内容发。

**自定义模板。** 可以在插件里新建模板，写标题、HTML 正文和纯文本正文，声明模板里用到的变量并给一个示例值。变量只用于预览和语法检查，实际发信时按当前收件人和填写的值渲染。站内模板可以一键复制成自定义模板再改，不用从空白开始。

**导出一份文件，改完再导回来。** 一个按钮把站内模板、自定义模板、插件自带的测试邮件和它们各自的变量导出成一份 JSON，文件里按 `builtin`、`custom`、`system` 三段分开，每段都带着自己可用的变量。这份文件可以直接交给编辑工具批量改样式，改完用「导入模板文件」读回来：插件先做一次只读核对，列出哪一条会更新、哪一条没变化、哪一条跳过、哪一条有问题，确认之后才真正写入。导入只修改同名的已有模板，不会新建也不会删除。

**隐藏与删除。** 两种模板都支持隐藏，隐藏后不出现在「写邮件」和「触发规则」的选择列表里，勾选「显示已隐藏」可以找回来。自定义模板是硬删除；站内模板由 Halo 自带，删掉之后 Halo 下次启动可能重新创建，想长期不出现请用隐藏。

**手动发信。** 选模板、选收件人、填变量就能发。收件人支持三种来源：站内用户（读取账号邮箱）、访客（从历史评论里提取邮箱地址）、手动输入任意地址（一行一个，逗号分号都认）。发送前可以预览，发送后逐条显示成功或失败和具体原因。

**触发规则。** 五种事件可选：文章或页面收到新评论、有新用户注册、有新文章发布、友链申请审核通过、友链申请被拒绝。收件人分两层：先选主要收件人（事件当事人、被评论文章的作者，或者只发给固定邮箱），再从站内用户、留言过的访客里勾人，也可以直接手填邮箱，选中的人都会额外收到一封。规则可以再挂一个 SpEL 条件，例如只在评论内容包含某个词时才发。规则只对启用之后产生的事件生效，不会把历史数据补发一遍。

**友链审核回信。** 站点装了「链接管理」插件（`PluginLinks`）时，插件会自动创建「友链审核通过回信」「友链审核拒绝回信」两个模板和对应的两条规则，审核通过或被拒绝后自动给申请人发信。收件人取申请里填的邮箱，从评论识别出来的申请没有邮箱时退回用那条评论的作者邮箱。

**给代码留的接口。** 打开开关后会生成一串触发密钥，外部脚本带上 `X-Mail-Key` 请求头就能调用 `POST /apis/mail.fufu520.cn/v1alpha1/trigger` 发信，模板名写 `builtin:模板名` 时使用 Halo 自带的通知模板。接口按来源 IP 限流，密钥可以在「发信设置」里重新生成，重新生成后旧密钥立即失效。

**发送记录。** 插件自己发出去的每一封都留档：收件人、模板、标题、状态、耗时和失败原因。点开任意一条可以看到当时发出去的完整样式、纯文本正文、去重键和规则名。列表能按来源筛选手动发送、自动规则、触发接口和站点通知。站点自己发出的站内通知也会一并收录。记录按设置的保留天数和条数上限自动清理。

关于「站点通知」这一类记录有两点要说清楚：Halo 发信走的是它内部的邮件通知器，插件拿不到 SMTP 调用，能观察到的只有 Halo 为每次投递创建的站内通知，所以这类记录的状态是「站点已发出」而不是「投递成功」；发给未注册访客的邮件（比如邮箱验证码）不会产生站内通知，因此收录不到。

## 发信通道

插件自己构造 SMTP 客户端，账号有两种取法，在「发信设置」里切换：

- **复用 Halo 的邮件通知配置**（默认）。直接读「设置 → 通知 → 邮件通知」里已经填好的 SMTP，站点原来能收到通知邮件，插件装上就能用。
- **自定义 SMTP**。单独填写服务器、端口、账号、密码和发信地址。密码保存在 Halo 的 Secret 里，不写进 ConfigMap，也不会在接口返回里出现。

两种方式都有「发送测试」按钮，失败时会指出具体原因（未启用、缺少服务器地址、连接被拒等），而不是只报一个失败。

## 环境要求

- Halo 2.26.0 及以上
- 站点已在「设置 → 通知 → 邮件通知」中启用邮件通知，或在插件里配置自定义 SMTP

## 安装

在 Halo 后台「插件 → 安装」里上传 `plugin-mail-center-1.0.0.jar`，启用后左侧「工具」分组下会出现邮件中心的入口。

## 从源码构建

```bash
# 前端
cd ui
pnpm install
pnpm build

# 后端
./gradlew build -x :ui:pnpmSetup -x :ui:pnpmInstall -x :ui:pnpmCheck -x :ui:assemble
```

产物在 `build/libs/plugin-mail-center-<version>.jar`。前端必须先构建，`ui/build/dist` 不存在时 `processUiResources` 不会报错，只会打出一个没有 `console/` 目录的空壳 JAR。

## 触发接口

```bash
curl -X POST 'https://your-domain/apis/mail.fufu520.cn/v1alpha1/trigger' \
  -H 'Content-Type: application/json' \
  -H 'X-Mail-Key: mc_xxxxxxxx' \
  -d '{
    "template": "mail-template-welcome-mail-a1b2c3",
    "to": ["someone@example.com"],
    "variables": { "code": "123456" }
  }'
```

响应里逐条给出每个收件人的结果：

```json
{
  "total": 1,
  "success": 1,
  "failed": 0,
  "results": [
    { "email": "someone@example.com", "success": true, "error": null, "logName": "mail-log-xxxx" }
  ]
}
```

可选的 `subject` 字段会临时替换模板标题。模板名以 `builtin:` 开头时（例如 `builtin:template-new-comment-on-post`）使用 Halo 自带的通知模板，其余按自定义模板名解析。

## 模板语法

模板用 Thymeleaf 渲染，和 Halo 自带通知模板完全一致：

```html
<p>你好 [(${subscriber.displayName})]，</p>
<p>你在 [(${site.title})] 的评论已经通过了。</p>
```

每个模板都自动带上这些值：

| 变量 | 说明 |
| --- | --- |
| `subscriber.displayName` | 收件人显示名，未填写时是邮箱地址 |
| `subscriber.email` | 收件人邮箱 |
| `site.title` / `site.subtitle` / `site.logo` / `site.url` | 站点基本信息 |
| `unsubscribeUrl` | 通知中心地址 |

站内模板的变量来自它所属通知类型的属性定义，自定义模板的变量来自模板自己的声明。触发规则额外提供事件相关变量：评论事件有 `commenter`、`commenterEmail`、`content`、`postTitle`、`postUrl`（自定义页面则是 `pageTitle`、`pageUrl`），注册事件有 `username`、`displayName`、`email`、`registeredAt`，发布事件有 `postTitle`、`postUrl`、`postAuthor`、`postSummary`，友链事件有 `displayName`、`websiteUrl`、`websiteDescription`、`websiteLogo`、`backlink`、`applicantEmail`、`reviewResult`、`approved`。

## 模板文件

「邮件中心」右上角的「导出模板文件」会生成这样一份 JSON：

```json
{
  "format": "mail-center-templates",
  "formatVersion": 1,
  "exportedAt": "2026-10-31T08:00:00Z",
  "siteTitle": "我的博客",
  "siteUrl": "https://example.com",
  "notes": ["……给编辑工具看的说明……"],
  "globals": { "variables": [ { "name": "site.title", "label": "站点名称", "type": "string" } ] },
  "builtin": [
    {
      "name": "template-new-comment-on-post",
      "reasonType": "new-comment-on-post",
      "reasonDisplayName": "文章收到新评论",
      "language": "default",
      "title": "[(${commenter})] 评论了你的文章",
      "htmlBody": "<p>…</p>",
      "rawBody": "…",
      "variables": [ { "name": "commenter", "label": "评论人", "type": "string" } ]
    }
  ],
  "custom": [
    {
      "name": "mail-template-friend-link-approved",
      "displayName": "友链审核通过回信",
      "subject": "……",
      "htmlBody": "……",
      "rawBody": "……",
      "enabled": true,
      "hidden": false,
      "variables": []
    }
  ],
  "system": [
    { "key": "test", "name": "mail-template-system-test", "subject": "……", "htmlBody": "……" }
  ]
}
```

改的时候只需要动 `title`、`subject`、`htmlBody`、`rawBody` 这四类字段，`name` 决定改的是哪一个模板，不要动。字段留空表示保持原样，未知字段会被忽略，单条写坏了也只影响那一条。

导入的行为是固定的：

- 只修改已经存在的同名模板，不新建、不删除；
- 先只读核对一遍，页面会列出每一条的结论，确认后才写；
- 内容没有变化的条目不会产生写入；
- `builtin` 写完会打上「已自定义」标记，Halo 升级不再覆盖；想恢复原样用「重置」。

## 友链审核回信

装了「链接管理」（`PluginLinks`）之后，插件会把两条规则和两个模板准备好：

| 规则 | 事件 | 模板 |
| --- | --- | --- |
| 友链申请通过后回信 | `LINK_APPROVED` | 友链审核通过回信 |
| 友链申请拒绝后回信 | `LINK_REJECTED` | 友链审核拒绝回信 |

模板是普通的自定义模板，标题、正文、收件人策略都能改；规则也能停用或删掉。四条默认内容只创建一次，并且用一个一次性标记记住这件事：上次启动中途失败留下的半套内容，下次启动会补齐；初始化完成之后再删掉任意一条，不会被重新加回来。

审核结果来自对友链申请状态变化的监听，而不是定时扫描：只有插件运行期间发生的通过 / 拒绝才会触发回信，启用之前已经处理完的申请不会补发。

如果规则匹配到了申请却没有可发的地址（申请没填邮箱、评论来源的作者也不是邮箱身份），或者规则指向的模板被删掉了，发送记录里会留一条「未发送」并写明原因，不会静默跳过。

## 数据模型

插件注册三个自定义模型，都在 `mail.fufu520.cn/v1alpha1` 组下：

- `MailTemplate` — 自定义邮件模板（插件自带的测试邮件也用它存，靠标签区分）
- `MailSendLog` — 发送记录，同时充当自动触发的去重台账
- `MailTrigger` — 触发规则

自动触发的去重靠记录名：规则名、事件类型、事件对象和收件人拼成一个键，取哈希作为记录名。同一条事件重复扫描时会先撞上已有的记录，因此重启、重新部署或扫描变慢都不会重复发送。

## 常见问题

**页面提示「读不到 Halo 的邮件通知配置」。** 说明「设置 → 通知 → 邮件通知」还没有启用或没有保存过。在那里填好并保存，或者到「发信设置」切换成自定义 SMTP。

**发送失败提示连接被拒或超时。** 多数是端口和加密方式不匹配：465 配 SSL、587 配 TLS，其余情况选不加密。部分邮箱要求使用授权码而不是登录密码。

**触发规则没有生效。** 检查规则是否处于启用状态，另外规则只处理启用之后产生的内容；评论事件默认只对审核通过的评论发信，可以在插件设置里关掉这个限制。

**删掉站内模板后它又回来了。** 站内模板来自 Halo 自带的资源文件，Halo 每次启动都会补齐缺失的那些，删除命令对它只有临时效果。想让某个模板长期不出现在列表里，用隐藏。

**友链审核后没有收到回信。** 先确认「链接管理」插件是启用状态，再检查两条友链规则的收件人策略；如果申请是从评论识别出来的、申请人也没填邮箱，插件会退回用那条评论作者的邮箱，两者都没有时这一条不会发，但发送记录里会出现一条「未发送」并写明原因。

**发送记录被清空会影响什么。** 自动规则靠记录去重。清空记录后，回看窗口内的事件有可能被重新发送一次。

**导入模板文件后没有变化。** 导入只匹配已经存在的模板，`name` 对不上就跳过，页面上会写「找不到同名模板」。另外内容完全一致的条目不算更新，统计里记作「无变化」。

**早于 1.3.0 的发送记录为什么看不到样式。** 邮件正文是 1.3.0 才开始随记录一起保存的，更早的记录只有收件人、标题和状态这些字段，详情面板会说明这一点。
